## 顺序和整体目标

1. **P0 提交准备，先于高优先级验证。** 清点 Demo 变更，区分运行代码、治理快照、计划与可公开证据；检查敏感内容、生成文件、暂存/工作区差异以及 Core 未提交依赖。以可复现构建和不泄露凭据为提交门禁，按逻辑单元提交；不覆盖既有工作或顺手清理用户文件。记录无法随代码提交的证据及其替代位置。当前有 1197 个未跟踪文件，且两项暂存重命名的目标在工作区又被删除；现有暂存区不能直接代表最终代码。Core 菜单修改尚未提交，须明确版本依赖并验证后处理。**状态：进行中。**
2. **P1 整体目标：可交付的平台最小闭环。** 同一可识别 Core 版本及 Demo 提交，在隔离环境完成前后端构建、启动、登录、动态菜单、系统管理和基础设施代表流程、权限/租户边界与数据库初始化/重启；保留历史密码。端到端证据、失败记录、资源清理及可重复命令齐备，才可标记 P1 完成。P1 是优先里程碑，不替代 T1/T3/T4 的全量验收。
3. **P2 业务主流程。** 对 Demo 已接入的会员和 ERP 按前端、API、数据库、权限、租户和关键事务完整路径验证，覆盖代表性正常及失败流程；核实业务模板独立迁移和复制流程。**状态：进行中，部分 ERP 流程已有隔离证据。**
4. **P3 全量扩展与低频故障。** 逐页完成 System/Infra 余下操作、原版对照、样式和响应式；补全 Controller/Mapper/Service 权限租户事务矩阵，以及 OAuth、社交、Quartz、文件存储、并发和故障注入。其他业务模板按业务优先级逐模块核对 SQL 与消费集成。**状态：待验证及部分进行中。**
